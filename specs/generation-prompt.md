# Generation Prompt

## How to Use

1. Edit the 7 values in the `Parameters` section below.
2. Copy everything between **---START PROMPT---** and **---END PROMPT---** and paste it into an AI assistant (Claude, ChatGPT, etc.) along with access to the `sample/` directory.
3. When the AI finishes, run the verification commands at the bottom to confirm the output builds.

---START PROMPT---

## Task

Generate a Flutter project based on `sample/`. Read every source file in `sample/`, substitute the parameter values wherever they appear, and write the result to a new project directory at the repo root (name it `<project_name>`).

Work file-by-file. Do not ask clarifying questions. Do not add features, comments, or files that do not exist in `sample/`.

## Parameters

```
project_name           = alex_wang
package_name           = co.alex.wang
app_name               = Alex Wang
app_version            = 0.1.0
build_number           = 1
json_field_rename      = snake
add_permission_handler = false
```

**Constraint:** `package_name` must be a valid Apple bundle identifier and Android namespace — only alphanumeric characters (`A-Z`, `a-z`, `0-9`) and periods (`.`). No hyphens, no underscores. Must be reverse-DNS format (at least one period). If the value above violates this, stop and report the error.

## Substitutions

Apply these substitutions wherever they appear in any text file in `sample/`. The staging variant must be replaced **before** the base variant — otherwise you will double-substitute.

| Find (in `sample/`) | Replace with |
|---|---|
| `co.nimblehq.flutter.template.staging` | `<package_name>.staging` |
| `co.nimblehq.flutter.template` | `<package_name>` |
| `co/nimblehq/flutter/template` | `<package_name>` with `.` → `/` |
| `Flutter Templates Staging` | `<app_name> Staging` |
| `Flutter Templates` | `<app_name>` |

## Skip list

Do not copy or generate these files — they are build artifacts or generated by tooling:

- Anything under `build/`, `.dart_tool/`, `ios/Pods/`, `.packages/`, `coverage/`
- `.flutter-plugins`, `.flutter-plugins-dependencies`, `Generated.xcconfig`, `flutter_export_environment.sh`, `local.properties`
- All `*.g.dart`, `*.freezed.dart`, `*.config.dart`, `*.mocks.dart` (build_runner produces these)
- `lib/gen/*` (flutter_gen produces these)

Copy binary files (`*.png`, `*.otf`, `*.keystore`) without modification.

## Structural changes (not substitutions)

### Android Kotlin directory

`sample/` has `MainActivity.kt` at `android/app/src/main/kotlin/co/nimblehq/flutter/template/`. In the generated project, this file must be at `android/app/src/main/kotlin/<package_name-with-dots-as-slashes>/`. The file contents already get substituted above; this is only about the directory path.

### Conditional: `add_permission_handler`

When `false`:
- Remove the `permission_handler:` line from `pubspec.yaml`
- Do NOT create `lib/utils/wrappers/permission_wrapper.dart`
- In `ios/Podfile`, delete the entire `config.build_settings['GCC_PREPROCESSOR_DEFINITIONS'] ||= [ ... ]` block (including its closing `]` and any trailing comma). Do NOT delete only the opening line — that leaves orphan array elements and invalid Ruby.

When `true`: keep both as-is from `sample/`.

## Architecture rules (must hold in the generated project)

- All Dart imports use `package:<project_name>/...` — never relative imports.
- `lib/domain/` must not import from `lib/data/` or `lib/app/`.
- `lib/data/` must not import from `lib/app/`.
- GitHub Actions workflow files: keep `${{ }}` syntax literally. Do not treat it as template syntax.

## Self-check

After generating every file, run this in the generated project directory:

```bash
grep -rn "co\.nimblehq\.flutter\.template\|package:sample/\|nimblehq/sample\|Flutter Templates\|name: sample" . \
  --include='*.dart' --include='*.yaml' --include='*.yml' --include='*.xml' \
  --include='*.gradle' --include='*.rb' --include='*.pbxproj' --include='*.xcscheme' \
  --include='*.plist' --include='*.properties' --include='*.pro' --include='*.md' \
  --include='*.kt' --include='*.swift' --include='*.json' --include='*.arb'
```

Any output means a substitution was missed. Fix it before reporting done.

## Verifying the output (run these yourself)

After the AI reports done, verify the project builds:

```bash
cd <project_name>
flutter pub get
dart run build_runner build --delete-conflicting-outputs
flutter analyze
flutter test
flutter build apk --debug --flavor staging -t lib/main.dart
flutter build ios --debug --no-codesign --flavor staging -t lib/main.dart  # macOS only
```

If all pass, the project is ready. If any fail, the error message identifies what needs fixing.

**Note on iOS release strings:** `flutter build` does not compile `ios/fastlane/Constants/Constants.rb` or the `APP_DISPLAY_NAME` entries in `ios/Runner.xcodeproj/project.pbxproj`. Verify these manually if you plan to ship:

```bash
grep -n "<package_name>" ios/fastlane/Constants/Constants.rb
grep -n "<app_name>" ios/Runner.xcodeproj/project.pbxproj
```

Both should show your substituted values, not the template defaults.
